# 4.5.0 F7: switch-over, monitoring, rollback, Safari decision

F7 changes no code, rules or Worker. It documents and guides turning on `content/guard.tokenRequired`.

## How the switch works
- Owner Panel > Security > Form verification toggles `content/guard.tokenRequired` (boolean). ON: the old direct write is refused by the rules and the page uses the code + one-time pass. OFF: both paths are allowed (instant rollback).
- That the old path is refused when ON is proven by the rules simulator (attack cases, section 8j) and emulator tests (164/164), not by a live write attempt.

## Rollback
Turn the switch OFF on the Security page. If the Security page itself is unreachable: Firebase console > Firestore > `content/guard` > set `tokenRequired` to false. If the rules were the problem: republish the previous `firestore.rules.strict` from the F4 ZIP.

## Monitoring (look weekly, or when something feels off)
| Where | What to check | Action |
|---|---|---|
| Security page | Today's count against the limit | Count hits the limit early in the day = possible lock-out attack: raise the limit, or pause intake, and point visitors to the email button |
| Cloudflare > Workers > portfolio-forms | Requests per day (free limit 100k) | A sudden spike = scripted abuse; per-visitor limits still apply |
| Firebase > Authentication | Users starting with `m_` | Delete them monthly (each token creates one) |
| Firebase > Usage | Writes (20,000/day) and reads (50,000/day) | Reads are the bigger risk (about 16 listeners per page visit): separate future phase |

## Safari decision (owner, 2026-11-06)
No Safari, iPhone or Mac tester is available. The owner decided to go live without Safari verification. The mailto "Email me instead" button is the safety net if verification fails in Safari. Revisit when a tester is found: one visit, one request, one screenshot. Not proven: Safari behaviour of the verified path.

## Honest limits (unchanged)
Code readable by scripts (speed bump, not a CAPTCHA); throttles per Worker instance; attacker can fill the daily cap (lock-out); Worker outage with the switch ON means visitors use the email draft only.
