# 4.5.0 R3: retention for Discovery Call requests (design record)

Release label: AUTOMATED_TESTED. Public repository: nothing secret here.

- Decisions (owner): flag unanswered at 90 days; finished requests deleted directly (no anonymize); confirmed-but-past counts as finished after meeting date + 30 days; banner once a week; backup warning is skippable.
- Logic: `scripts/core-retention.js` classifies one request (keep / flag / due). Unknown status, missing or future createdAt, bad meeting date => keep. The meeting end uses the end of the date in UTC+14 so a meeting is never treated as past early. Settings come from `settings/site.retention` (`requests`, `reqFlag`, `reqStale`), validated to integers in range, flag always before delete.
- Query: `createdAt < now - min(flag, finished)` ordered, 400 per page with `startAfter`, at most 6 pages (2400 reads) per check; the preview says when more may remain. Cost on Spark: far inside 50,000 reads/day and 20,000 deletes/day.
- Delete safety: owner-only (existing rule); preview first; each request re-read and re-classified immediately before deletion; sequential, so a stop can be resumed by pressing Check again; activity log records counts only.
- Banner: checked on owner sign-in at most once per 7 days (`ownerPrivate/config.retBannerAt`); counts only.
- Privacy page text and `privacy-notice.js` show the periods (`pvReq`, `pvStale`).
- Bug fixed on the way: the old `due()` repeated its first page when 400 or more records matched; now cursor-paged.
- Not covered: Google Sheet copies, backup files, calendar events, "m_" Auth users (manual checklist).
