# 4.5.0 D1: Owner documents (private notes and runbooks)

## What it is
An owner-only page in the Owner Panel (drawer > Settings > Owner documents). Documents are stored in Firestore `ownerDocs/{id}` with fields `title` (1 to 120 characters), `category` (security, runbook, notes, other), `body` (up to 50,000 characters), `createdAt`, `updatedAt` (both server time).

## Security
- Rules (`firestore.rules` and `firestore.rules.strict`, appended after `content/{doc}`): only the owner can read, list, create, update or delete. Field whitelist, exact types, length limits, id pattern `^[a-z0-9]{8,32}$`, `createdAt == request.time` on create and unchanged on update, `updatedAt == request.time` always.
- The page shows document text with `textContent` only, so no HTML or script in a document can ever run.
- The page and the helper refuse text that looks like a private key, Google API key, webhook address, GitHub or Slack token, sign-in token or a password/token assignment. This is a safety net, not a guarantee; secrets belong only in Cloudflare secrets.
- Visitors load nothing from `ownerDocs` and the page content is not part of the public site.
- Backup: export only (the rules need server timestamps, so a restore would be refused anyway).

## Tests
`rules-tests/attack/attack_cases.py` section 8k (24 checks on both rules files, total 2433), 22 mutations in `mutations_d1.py` (+2 redundant guards labelled EQUIV), `rules-tests/emulator/docs-d1.test.mjs` (23 tests, to be run by the owner in GitHub Actions), `scripts/owner-docs-core.test.mjs` (8 tests), browser check with mocked Firebase (20 checks).

## Limits
Documents are as private as the owner's Google sign-in. 1 MB Firestore limit per document is not reachable (50,000 characters). No version history. Search is plain text. Moving existing public files into the portal is a separate step; old public versions remain in GitHub history.
