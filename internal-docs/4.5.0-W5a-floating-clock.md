# 4.5.0 W5a: floating WorkTrack clock

Status: **AUTOMATED_TESTED** (awaiting the owner's live test, then MANUALLY_VERIFIED). Not PRODUCTION_APPROVED.

## What it does
- While you are signed in as owner and a WorkTrack session is open, a small clock floats on top of the page (top right by default).
- It shows the time in the session's time zone, the status (Working, On lunch, ...), working time so far, and ONLY the punch buttons that are legal right now. Clock out asks for a second press ("Confirm: Clock out", 5 seconds).
- Drag it by the grip or the bar; arrow keys move it 10 px (Shift = 50 px); Home puts it back. It cannot leave the window. "Minimise" shrinks it to one line. Position and minimised state are remembered on this device only (`localStorage` key `wtFloat:v1`).
- It stays visible when you leave the dashboard for the public site. It disappears when you clock out or sign out.
- R1 (QA): the dashboard is an `aria-modal` dialog, so while it is open the clock moves INSIDE it (keyboard Tab and screen readers reach it) and returns to the page when it closes. Inside the dashboard its default place is just below the header buttons.

## What it does NOT change
No database change. `firestore.rules`, `firestore.rules.strict`, the eight-punch state machine (`core-worktrack.js`), punch records and the sealed log are untouched. Every punch from the clock goes through the same single transaction as the WorkTrack page buttons (`wtApi.punch` calls the existing `punch()`).

## Database cost (free plan)
- Owner sign-in or page open: one load of the WorkTrack state (state record, events and assignments of the open session, session record): at most about 4 reads. Nothing is read when no session is open beyond the state record (1 read).
- Focus or tab return: at most ONE read of `workState/main` per minute; a full reload only if its revision changed (another device punched). No timers poll the database. The clock's own ticking is local.

## Honest limits
- Not tested: real database, Safari, real phone touch, real screen reader (headless stub only).
- The clock shows the time estimated from the website server's `Date` header (same as the WorkTrack page); it can differ from the database punch time by about 1 second. Saved punch times are always the database's.
- A second device's punch shows after the next focus check (up to one minute plus focus), not instantly.
- On a phone the default top-right place can cover the site header; drag it elsewhere (it remembers).
- The clock cannot ring or remind while the browser is closed; reminders are W5c and are browser-only.

## QA review audit: meeting Confirm step (read-only, no change needed)
`setReq(r, 'confirmed')` in `owner-dashboard.js` checks the live request list for an overlapping confirmed meeting (duration-aware, `availApi.conflict`) and, when Google Calendar is connected, asks the calendar. Either warning offers "Confirm anyway" (an owner decision, not a block). `content/busy` is rebuilt from the live confirmed list 0.9 s after any change. A visitor request is only `status: new`, never a booking. With one owner and a live list, a silent double confirmation is not possible; an intentional one needs two explicit clicks. Residual: the visitor-side `slotFree()` rule is best effort by design. No transaction was added.
