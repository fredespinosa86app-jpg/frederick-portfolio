# T2: icon buttons on the other dashboard pages (delivered)

Approved with the layout recommendations: one phase, plus icon on Add buttons, no new Duplicate actions, workflow/status buttons stay text.

Measured scope (code scan): 8 files in the layout, 11 in the build (the scan after the build also found `owner-billing.js` and the Inbox question delete in `owner-dashboard.js`, both converted). About 17 row-button sets, about 60 buttons.

Design
- `dashKit.iconBtn(icon, action, name, onClick, opts)` from T1 is the only button builder. Accessible name `Action: Name`, tooltip `Action`.
- `ctl` (owner-content.js, shared via `ownKit` with phase1/2/5/6) maps `Move up/Move down/Edit/Rename` to `up/down/pencil/pencil`; other labels keep the text button (for example `Preview`, `Next month`).
- `del` exists twice (owner-phase1.js, owner-phase2.js): both now `iconBtn('trash', 'Delete', ...)` with `danger`.
- Inline delete buttons in owner-content, owner-phase5, owner-phase6 were converted by one scripted rewrite (four, one, three sites) keeping the label text ("Delete category: Name").
- Client IDs: copy / pencil (edit note) / clock (history) / archive (danger) or restore. Documents: eye / pencil / trash. Library card: pencil. Billing profiles: pencil, clock. Inbox question delete: trash.
- New symbols `ic-archive`, `ic-eye` in `index.html`; Add buttons are `class="dbtn ... ibtn"` with `<svg><use href="#ic-plus"/></svg><span>Text</span>`.
- `.dbtn.ibtn` styles from T1 are reused unchanged.

Tests: `scripts/icon-buttons.test.mjs`, `rules-tests/browser/t2-1-icon-buttons.mjs`. The static test fails when a row-action text button comes back (allow-list: the library dialog Delete). The browser test seeds each page through the public APIs (`contentApi`, `testiApi.setDoc`, `faqApi`, `videosApi`, `experienceApi`, `chatEngine.setKb({items})`) and stub-store documents (`clientRegistry`, `ownerDocs`).

Not covered by automated tests: Clients (Firestore snapshot), Library, Billing profiles, blocked periods and the Inbox question delete are converted through the same helper but are covered by the static test and the live checklist only.
