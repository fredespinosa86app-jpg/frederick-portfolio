# 4.5.0 W1 - WorkTrack schema and rules (internal)

This repository is public. Nothing secret belongs in this file.

## Collections (owner only, create-only except the state record)
| Path | Fields | Notes |
|---|---|---|
| `workState/main` | state, sid, n, fb, lu, lb, lastEid, rev, updatedAt | One record. Moves one valid step per punch; `rev` +1 serialises two tabs. Created once in its starting form. Never deleted. |
| `workSessions/{sid}` | tz, date, startedAt, by | One per session. Created in the same transaction as the first event. |
| `workEvents/{sid}__{n}` | sid, n, type, at, by, reason | `at` = server time. `reason` only for CLOSE_INCOMPLETE (3-200 chars). Counter n = 1..12. |

## Transition table (same table in `scripts/core-worktrack.js` and in `wkStep()` of the rules)
NOT_STARTED: CLOCK_IN. WORKING: FIRST_BREAK_OUT / LUNCH_OUT / LAST_BREAK_OUT (each once), CLOCK_OUT, CLOSE_INCOMPLETE. FIRST_BREAK: FIRST_BREAK_IN, CLOSE_INCOMPLETE. LUNCH: LUNCH_IN, CLOSE_INCOMPLETE. LAST_BREAK: LAST_BREAK_IN, CLOSE_INCOMPLETE. Everything else is refused with a reason.

## Pattern
One punch = one transaction (event + state [+ session]). The event rule reads the state before (`get`) and after (`getAfter`) and requires exactly one valid step; the state rule requires a brand-new paired event and revision +1. Clock in also requires a brand-new session record.

## Honest limits
Rules cannot compute hashes (W3 adds detection). Time zone and date text of a session are page-supplied (shape-checked only). Console access can change data.
