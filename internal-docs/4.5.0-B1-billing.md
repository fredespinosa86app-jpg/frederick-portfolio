# 4.5.0 B1 - billing profiles, billable hours, migration (internal)

This repository is public. Nothing secret belongs in this file.

## Collections (all owner only, no delete)
| Collection | ID | Notes |
|---|---|---|
| `billingProfiles` | Client ID | currency, exp, rateMinor, arrangement, schedKind, weekStart, anchors, genTime, tz, dueKind, dueDays, dueDate, rev, createdAt, updatedAt, lastAudit. Create needs an active registry entry (or one created in the same batch). |
| `billingProfileAudit` | 16-40 alphanumerics | create-only: clientId, action (create/update), rev, currency, rateMinor, arrangement, summary, reason, actor, createdAt. Mirrors the profile after the batch. |
| `billableEntries` | `CLIENTID__YYYYMMDD__YYYYMMDD__NN` | status DRAFT / SUBMITTED / APPROVED / SUPERSEDED, submittedMinutes, approvedMinutes (null until approved), supersedes / supersededBy, approvedAt, approverUid, relatedInvoiceId (empty until B2), rev. |
| `billableEntryAudit` | 16-40 alphanumerics | create-only: one per step (create, edit, submit, reopen, approve, supersede). |
| `billingMigration` | old `clients` document ID (10-40 alphanumerics) | create-only: clientId, profileNew, registryNew, arrangement, by, createdAt. |

## Rule patterns
- "Paired audit write": record and a brand-new audit record in ONE batch (`!exists` before, `existsAfter` after), revision +1, audit mirrors the after-state, the audit's `rev` equals the stored revision + 1.
- Entry state machine in the rules: edit (DRAFT), submit, reopen (reason in the audit), approve (server time, own UID, approved minutes), supersede (APPROVED -> SUPERSEDED, the new DRAFT is in the same batch and points back). The minutes of an APPROVED or SUPERSEDED entry cannot be changed by any rule branch.
- Migration: the mapping create requires `!exists` of the profile and the profile in the same batch at revision 1; a new registry entry may be created in the same batch (the profile create accepts that).
- Rules cannot loop or hash: custom anchor order/range and the audit summary text are page checks (see KNOWN-ISSUES).

## Tamper-evident log
`core-wtlog.js` `COLLECTIONS` now also covers `billingProfileAudit`, `billableEntryAudit`, `billingMigration` (field `createdAt`). The pages announce new audit paths with the `wt:written` event and the existing W3 code seals them.

## Money and time
Rates are integer minor units (`core-money.js`: USD/GBP/EUR/AUD/CAD/PHP 2, JPY 0, KWD 3), at most 1,000,000,000. Minutes are integers 1 to 133,920 (93 days). Periods are typed by the owner (max 93 days); B3 generates periods from the schedule.
